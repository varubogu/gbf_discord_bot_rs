# message_text ルール違反修正計画（2026-02-19）

## 目的
本計画は、メッセージ文言の管理ルール（DB/YAML優先、直書き禁止、ログ文言例外、Enumキー運用）に対する現状差分を是正し、実装と設計書を一致させるための修正方針を定義する。

## 対象ルール（再掲）
1. 優先順位: `guild message_text(DB)` → `global message_text(DB)` → `locales/messages.yml` → プログラム中フォールバック  
2. Discord送信文言は直書き禁止（DB/YAML未定義時のみフォールバック許可）  
3. ログ専用文言はプログラム中直書き可  
4. `messages.yml` キーは `MessageTextId`（Enum）で扱い、文字列キー直書きを避ける

## 調査結果

  - メッセージ解決順序 `guild -> global -> messages.yml`（`docs/ja/開発者向け/06_機能仕様/メッセージ解決.md:24`-`26`）

## 修正方針
1. 仕様を先に揃える（設計書更新）
- ルール1の最終段フォールバック（コード直書きは限定的許可）を `メッセージ解決` 仕様へ明記
- ルール3（ログ文言例外）を `コーディング規約` か `ロギング` に明記
- ファイル名表記を `messages.yml` に統一（`message.yml` と混在させない）

2. 実装を段階移行する（影響大のため一括置換しない）
- `events` 層の Discord 応答文言を最優先で `MessageTextId` 化
- `presenter` / `facade` の UI文言を次段で `MessageTextId` 化
- フォールバック文言は「YAML欠損時のみ」に統一し、通常経路の直書きを廃止

3. Enum運用を強制する
- `get_message_from_context` への文字列キー渡しを廃止し、`MessageTextId` 専用に寄せる
- 文字列キー直書きの新規混入を防ぐ静的チェックを追加

- 対応:
  - 直書き文言を `locales/messages.yml` に追加
  - `MessageTextId` バリアント追加
  - 既存 `unwrap_or_else` は「最終フォールバック」のみ残す

### Phase 3: presenter/facade層の直書き解消
- 対象:
  - `src/presenter/auto_recruitment_presenter.rs`
  - `src/presenter/notification_presenter.rs`
  - `src/presenter/recruitment_presenter.rs`
  - `src/presenter/schedule_presenter.rs`
  - `src/facades/auto_recruitment/category_setup_facade.rs`
- 対応:

  - 文言組み立てはテンプレート + パラメータ置換へ寄せる

### Phase 4: `AppError` 経由文言の整理
- `AppError::user_message()` の固定文言を `MessageTextId` ベースへ移行
- `main.rs` の error handler で `MessageService` 解決を通す設計に変更

### Phase 5: 監査ガード追加
- CI向け検査追加（例: `rg` ベース）
  - `get_message_from_context(..., \"...\")` を禁止
  - Discord送信APIへの文字列リテラル渡しを禁止（ログマクロは除外）
