# マルチ募集メッセージでロールに対してメンションする機能を追加

マルチバトル募集について仕様を加えたい。
まず設計書を作成・修正し、その後コード修正してください

# 概要
- マルチ募集開始時、変更時、キャンセル時のメッセージにて、guildごとに追加でロールメンションを追加する
- クエストごとのロール設定コマンドを作成する。※詳細は「ロール設定コマンド仕様」にて

# ロールについて
ロールは大きく2種類
- 全ての募集を通知するロール
- クエストに応じた通知をするロール

# データベース仕様
- テーブルを２つ追加する（全ての募集通知ロール、クエストごとの通知ロール）
- 列はguild_id(bigint),クエストID(int),連番(int),ロールID(bigint)、作成日時、更新日時を保持する（全ての募集通知の場合、クエストID列を除外）
- guild_id,クエストIDと連番のセットでPKとする（全ての募集通知の場合、クエストIDのみ除外）
- guild_id,クエストIDとロールIDのセットでユニークとする（全ての募集通知の場合、クエストIDのみ除外）
- クエストIDは外部キー制約を登録する→master.quests.id
- 連番はauto_increment
- 連番は表示順序の保証にも利用する（後から追加されたものは後に出る）
- 高速化のためのインデックス戦略としてguild_id,クエストIDでインデックス、guild_id,クエストIDとロールIDでインデックスをする
- 作成日時、更新日時は他テーブルと同じ仕様とする
- guild_idがあるのでRLS対象のテーブルである
- guildに関するテーブルなのでguild_masterスキーマに入る

```
guild_master.all_recruitment_notification_roles
  - guild_id (bigint, PK)
  - seq (int, PK, auto_increment)
  - role_id (bigint)
  - created_at, updated_at
  - UNIQUE: (guild_id, role_id)

guild_master.quest_recruitment_notification_roles
  - guild_id (bigint, PK)
  - quest_id (int, PK, FK → master.quests.id)
  - seq (int, PK, auto_increment)
  - role_id (bigint)
  - created_at, updated_at
  - UNIQUE: (guild_id, quest_id, role_id)
```

# ロール設定コマンド仕様
- 追加コマンドと削除コマンドを用意する（パラメータの仕様は同じ）
- パラメータ1として、マルチ募集と同じようにクエスト入力欄を用意する
- クエスト入力欄の先頭には「すべて」という項目を追加し、内部的にはquest_id=0として扱う
- パラメータ1が「すべて」（quest_id=0）なら、全ての募集通知ロールのテーブルに登録する
- パラメータ1が上記以外ならクエストごとの通知ロールのテーブルに登録する
- パラメータ2〜7でロールを入力する（discordスラッシュコマンドのロール型パラメータを使用する、一度に最大6ロールまで設定可能）
- パラメータ1と2は必須、3以降は全てオプション
- 追加コマンドで既に追加済みのロールがあった場合、そのデータはDBへinsertせず正常完了扱いとする
- 削除コマンドで既に存在しないロールがあった場合、そのデータはdeleteせず正常完了扱いとする
- 入力ロールが実際に存在しない場合はコマンドはエラーとしてコマンドを終了する（bot自体は終了しない）
- このコマンドを利用できるのはサーバーごとの管理者用コマンドを実行できる「gbf_bot_control」ロールを持つ人のみ

# マルチ募集追加、変更、削除コマンドの修正内容
- ３つのコマンドそれぞれで、クエストに応じたロールをメンションする
- DBから該当ロールを探す条件は (クエストID == 0 or クエストID == 募集するクエストのクエストID)
- 順番はクエストIDの昇順、連番の昇順
- 検索されたロールについて、全ての募集通知、クエストごとの募集通知の順で検索結果を全部つなげて良い。`@マルチ募集 @天元募集`
