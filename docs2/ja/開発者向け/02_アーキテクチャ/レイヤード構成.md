# レイヤード構成（開発者向け）

## 目的

機能追加や修正をしても破綻しにくいように、責務を分けて依存方向を固定します。

## 依存方向（重要）

このプロジェクトは、原則として次の一方向に依存します。

`events → facades → services → repository`

### 各層の責務（ざっくり）

- **events（プレゼンテーション層）**: Discordの入力を受け、入力検証し、Facadeを呼び出す
- **facades（アプリケーション層）**: ユースケース単位でサービスを組み合わせる。トランザクション境界を管理する
- **services（ドメイン/業務処理）**: 業務ルールを実装し、Repositoryを使って入出力する
- **repository（永続化）**: DBへの読み書きのみを担当（業務判断はしない）

## トランザクション（重要）

- **トランザクションの開始/コミット/ロールバックは Facade 層のみ**
- Serviceは「受け取ったトランザクション」を下位（Repository）へ渡します

## 禁止事項（代表）

- events から services / repository を直接呼ぶ
- facade から repository を直接呼ぶ（サービスを経由する）
- repository に業務ロジックを書く
