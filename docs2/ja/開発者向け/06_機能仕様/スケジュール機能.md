# スケジュール機能

## 概要

本機能は、`worker.scheduled_tasks` を中心に「指定時刻に処理を実行する」ための共通基盤です。
現在の実装では、イベント通知だけでなく、定期募集・解散・自動募集系タスクも同じ基盤で実行します。

## 目的

- 実行時刻と処理種別をDBで一元管理し、時刻到達時に確実に処理する
- 通知系と募集系の時刻実行を統一し、処理方式を揃える
- 実行対象が欠損・無効化されても安全にスキップし、全体停止を回避する

## 代表ユースケース

- イベントスケジュールから通知タスクを再生成し、時刻になったら通知する
- 定期募集スケジュールから次回募集タスクを作成し、連続実行する
- 募集の解散・人数不足解散を時刻実行する
- 自動募集ローテーションと自動マッチングを定期実行する

## 実行アーキテクチャ

### 起動時

- `main.rs` で `SchedulerManager` を初期化し、バックグラウンド起動する
- `tokio-cron-scheduler` のジョブで **10秒間隔** 実行

### 1サイクルの処理

1. 現在時刻から20秒先までの未実行タスク（`is_executed = false`）を取得
2. `schedule_datetime <= now` のタスクのみ実行
3. `task_type` ごとに Executor / Service を切り替えて処理
4. 処理完了後に `scheduled_tasks.is_executed = true` を更新（または次回タスクを登録）

## タスク種別（`ScheduledTaskType`）

- `1: Notification`
  - イベント通知、募集出発通知など
  - `notifications` と連携して Discord 送信
- `2: Dissolution`
  - 募集解散タスク
  - `scheduled_task_dissolutions` 経由で募集IDを取得して実行
- `3: DataCleanup`
  - 予約ありだが実行未実装（現状は警告ログのみ）
- `4: RecurringRecruitment`
  - 定期募集タスク
  - 実行時に募集作成後、次回タスクを再登録
- `5: Dismissal`
  - 人数不足解散タスク
  - `scheduled_task_dismissals` / `battle_recruitment_dismissals` と連携
- `6: AutoRecruitmentRotation`
  - 自動募集の日付ローテーション
- `7: AutoMatching`
  - 自動マッチング処理

## スケジュール生成（イベント通知）

`/schedule_generate` は `SchedulerFacade -> SchedulerService` を通じて通知タスクを再生成します。

1. `notification_rel_event_schedules` を全削除
2. `task_type = Notification` の `scheduled_tasks` を削除（関連 `notifications` はCASCADE）
3. `event_schedules` / `event_schedule_details` / 通知対象チャンネルを取得
4. `ScheduleCalculator` で通知日時を計算
5. `scheduled_tasks` -> `notifications` -> `notification_rel_event_schedules` の順で作成

### 日時計算の仕様（`ScheduleCalculator`）

- `start_day_relative` 対応
  - `*` / `all`, `start`, `end`, 単数値（例: `-1`, `5`）, 範囲（例: `0-30`, `0 to 30`）
- `time` は `%H:%M:%S` または `%H:%M` 形式
- 計算基準はイベント時刻（JST前提）をUTCへ変換して保存
- イベント期間外オフセットは `max_schedule_days_outside_event` 以内に制限

## 関連コマンド（管理者向け）

- `/schedule_generate`
  - 通知スケジュール再生成
- `/schedule_list`
  - 未来の通知予定を最大10件表示
- `/schedule_history`
  - 過去通知履歴を日数指定で表示
- `/schedule_stats`
  - 通知件数と `message_text_id` 別統計を表示

## 関連テーブル（主要）

| テーブル名 | 役割 |
| --- | --- |
| `worker.scheduled_tasks` | 実行時刻・処理種別・実行状態を持つ中核テーブル |
| `worker.notifications` | 通知送信対象（guild/channel/message_text_id, is_sent） |
| `worker.notification_rel_event_schedules` | 通知とイベントスケジュール明細の関連 |
| `worker.notification_rel_battle_recruitments` | 通知と募集の関連 |
| `worker.scheduled_task_recurring_recruitments` | 定期募集タスクと募集スケジュールの関連 |
| `worker.scheduled_task_dissolutions` | 解散タスクと募集の関連 |
| `worker.scheduled_task_dismissals` | 人数不足解散タスクと解散設定の関連 |
| `worker.scheduled_task_cleanups` | クリーンアップ対象のメタ情報（実行側は未実装） |

## 制約・注意点

- タスク実行は1サイクル内で同一トランザクションに集約される
- 個別タスク失敗時はエラーログを出して継続し、他タスクは続行する
- `task_type=3 (DataCleanup)` は現状未実装
- 実行対象データ欠損時は警告を出し、実行済みマークで再試行ループを防ぐ経路がある
- 通知送信で `message_text_id == "-"` の場合は送信スキップ扱い
