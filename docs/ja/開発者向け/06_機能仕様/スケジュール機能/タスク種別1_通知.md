# タスク種別1: 通知（Notification）

## 概要

`task_type = 1` は通知送信タスクです。  
現行実装では主に次の2系統で使われます。

- イベントスケジュール通知（global / guild の統合結果を通知）
- マルチ募集の出発通知（5分前・出発時刻）

## 登録フロー

### 1) イベントスケジュール通知

`SchedulerService::generate_and_persist_schedules` で以下を作成します。

1. `scheduled_tasks`（`task_type=1`）
2. `notifications`
3. `notification_rel_event_schedules`

詳細仕様は [イベントスケジュール通知.md](イベントスケジュール通知.md) を参照してください。

### 2) マルチ募集の出発通知

`NotificationManagementService::create_recruitment_departure_notification` で以下を作成します。

1. `scheduled_tasks`（`task_type=1`）
2. `notifications`
3. `notification_rel_battle_recruitments`

補足:

- 出発5分前通知は「現在時刻より未来」の場合のみ作成
- 出発時刻ちょうどの通知は常に作成

## 実行フロー

`SchedulerManager` の `task_type=1` 分岐で以下を実行します。

1. `task_id` から `notifications` を取得
2. `NotificationService::send_single_notification` を実行
3. 送信成功時は `scheduled_tasks.execution_status = succeeded`
4. 送信失敗時は `failed`

`send_single_notification` の要点:

- `message_text_id == "-"` は送信スキップ扱いで成功
- `notification_rel_battle_recruitments` がある通知は「募集通知」として返信形式で送信
- リレーションがない通知は通常通知として送信
- 送信後は `notifications.is_sent = true` を更新

## 実行状態とエラー制御

- `notifications` が見つからない: `succeeded_with_warning`（不整合を警告して次回自動再実行しない）
- 送信処理エラー: `failed`
- 通知取得クエリエラー: `failed`
