# タスク種別6: 自動募集日付ローテーション（AutoRecruitmentRotation）

## 概要

`task_type = 6` は自動募集の日付チャンネルを日次で更新するタスクです。  
対象は全ギルドで、`scheduled_tasks.guild_id` / `channel_id` は `NULL` で管理します。

## 登録フロー

- 初回登録: 自動募集カテゴリ登録時（`category_setup_facade`）
- 再登録: 実行完了時に翌日0時（JST）を次回として自己再登録

初回登録時は pending タスクを確認し、`task_type=6` が既にある場合は重複作成しません。

## scheduler連携時の依存方向

- `SchedulerManager` を合成ポイントとし、`crate::di::Repositories` から受け取った具象Repositoryを利用して実行系を組み立てる。
- 具象Repository実装は `src/infrastructure/database/repositories/**`（SeaORM実装）に配置する。
- `AutoRecruitmentRotationTaskExecutor` は `crate::repository` 経由のtrait（`ScheduledTaskRepository` / `AutoRecruitmentChannelRepository` / `AutoRecruitmentRepository`）に依存し、`SeaOrm*Repository` 具象型へ直接依存しない。
- 依存方向は `scheduler_manager（合成） -> executor -> repositoryポート` を維持する。
- 具象アダプターの配置先は `src/infrastructure/database/repositories/**` に統一する。

## 実装参照パス

```text
src/services/schedule/scheduler_manager.rs

src/repository/auto_recruitment/auto_recruitment_channel_repository.rs

src/infrastructure/database/repositories/auto_recruitment/auto_recruitment_repository.rs

src/di/repositories.rs
```

## 実行フロー

`SchedulerManager` の `task_type=6` 分岐で `AutoRecruitmentRotationTaskExecutor` を実行します。

1. タスク存在と `pending` を再確認
2. `auto_recruitment_channels` を全件取得
3. ギルドごとにチャンネルを日付順で処理
4. 過去日チャンネルを「現在の最大日付+1日」に更新
5. DBの日付更新後、Discordチャンネル名を `X月Y日` へ変更
6. チャンネル位置を並び替え  
   （`matching=0` → 日付チャンネル `1..n` → `quest=n+1`）
7. 現在タスクを `succeeded`
8. 次回タスク（翌日0時JST）を作成

## 実行状態とエラー制御

- ローテーション対象が0件でも `succeeded` とし、次回タスクを作成
- チャンネル名更新失敗はログ出力のみで処理継続
- チャンネル並び替え失敗もログ出力のみで処理継続
- 実行中の致命的エラーは `SchedulerManager` 側で `failed`

## 実装上の注意

- 日付判定は JST（`UTC + 9`）基準です。
- 無効日付（例: 2/30）はスキップします。
- 年跨ぎを考慮した比較ロジックを持ちます。
