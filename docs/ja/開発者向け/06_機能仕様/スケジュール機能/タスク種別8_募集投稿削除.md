# タスク種別8: 募集投稿削除（RecruitmentMessageDeletion）

## 概要

`task_type = 8` は、マルチ募集のクエスト出発時刻から設定分数が経過したあと、元のDiscord募集投稿を削除するタスクです。

このタスクは `worker.battle_recruitments` の行、キャンセル通知返信、解散通知返信、その他のDBデータを削除しません。削除対象は `battle_recruitments.channel_id` と `battle_recruitments.message_id` が指すDiscord募集投稿のみです。

## 登録フロー

- 手動募集: `/マルチバトル募集` と `/マルチバトル募集2` で募集行を作成したときに削除タスクを作成します。
- 定期/自動募集: 共通の募集作成サービスを通じて `worker.battle_recruitments` に行を作成する経路では、同じ削除タスクを作成します。
- 出発日時変更: その募集に紐づく未実行の削除タスクを削除し、現在の設定で再作成します。
- 募集キャンセル: 削除タスクは削除・再計算しません。元の募集投稿は予定済みの削除時刻で削除します。

## 猶予時間の設定

猶予時間は分単位で指定します。

```text
MULTI_RECRUITMENT_DELETE_AFTER_DEPARTURE_MINUTES
```

解決順序:

1. ギルド環境変数（`guild_master.guild_environments`）
2. グローバル環境変数（`master.environments`）
3. プログラム固定値 `10080` 分（7日）

未設定の場合は次の優先順位へフォールバックします。空文字、不正な数値、0以下の値も次の優先順位へフォールバックし、警告ログのみ記録します。設定フォールバックによるユーザー向けメッセージは出しません。

設定変更は、変更後に作成された募集と、変更後に出発日時が変更された募集へ反映します。既に作成済みの未実行削除タスクは自動再計算しません。

## 実行フロー

`TaskDispatchService` の `task_type=8` 分岐で `RecruitmentMessageDeletionTaskExecutor` を実行します。

1. タスク存在と `pending` を再確認
2. `worker.scheduled_task_recruitment_message_deletions` を `task_id` で取得
3. `BattleRecruitmentsRepository::get_by_id_with_txn` で対象募集を取得
4. `message_id != 0` の場合に `DiscordMessageGateway::delete_message(channel_id, message_id)` を呼び出す
5. 結果に応じてタスク状態を更新

## 実行状態とエラー制御

- Discord削除成功: `succeeded`
- 関連行なし: `succeeded_with_warning`
- 募集行なし: `succeeded_with_warning`
- `message_id = 0`: `succeeded_with_warning`
- Discord NotFound（`10008` メッセージなし、またはGatewayの `NotFound`）: `succeeded_with_warning`
- 権限不足や一時的なDiscord API失敗: `failed`
