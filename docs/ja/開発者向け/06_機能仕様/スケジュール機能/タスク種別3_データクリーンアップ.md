# タスク種別3: データクリーンアップ（DataCleanup）

## 概要

`task_type = 3` はデータクリーンアップ用の種別です。  
`scheduled_task_cleanups` テーブルおよびRepositoryは存在しますが、`SchedulerManager` の実行経路は未実装です。

## スケジューラー経路（現状）

`SchedulerManager` の `task_type=3` 分岐は以下の挙動です。

1. `DataCleanupタスクは未実装` を警告ログ出力
2. 対象タスクを `failed` に更新

このため、`scheduled_tasks` 上の `task_type=3` は現状そのままでは実行されません。

## 現行のクリーンアップ実行経路

実際のクリーンアップは `src/bin/cleanup.rs` から `DataCleanupService` を起動して実施します。

### 実行条件

- 保持期間: `CLEANUP_RETENTION_DAYS`（未設定時は30日）
- 実行主体: メンテナンス用バッチ（メンテナンスコンテナ想定）

### 削除内容（`DataCleanupService`）

1. `battle_recruitments` の期限超過・募集終了データを削除
2. `scheduled_tasks` の期限超過・非pendingデータを削除  
   （ただし `task_type=3` は除外）
3. `notifications` は `scheduled_tasks` 側のCASCADE削除で整理  
   （`cleanup_notifications` は現状 `0` を返す実装）

## 実装上の注意

- `scheduled_task_cleanups` は現行フローで参照・更新されません。
- 将来的にスケジューラー統合する場合は、`task_type=3` 分岐に専用Executor追加が必要です。
