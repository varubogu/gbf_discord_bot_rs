# マルチバトル募集オートマッチング機能 設計書

## 概要



ユーザーが希望するクエストと参加可能時間を事前登録し、条件が一致する他のユーザーと自動的にマッチングして募集を行う機能です。カテゴリチャンネルを活用し、日付ごとのチャンネルで参加時間を、クエストチャンネルで希望クエストを管理します。

## 機能の流れ

1. ユーザーがDiscord上でカテゴリを作成
2. カテゴリ登録コマンドで自動募集機能を有効化
3. Botが各種チャンネル（マッチング、日時、クエスト）を作成
4. 必要に応じて日数変更コマンドで募集期間を調整
5. ユーザーがクエストチャンネルで希望クエストを登録、日時チャンネルで参加可能時間を登録（順不同）
6. 周期マッチング処理（10秒間隔）で2人以上が同じ日時・同じクエストを希望した場合、マッチング成功
7. マッチングチャンネルに通知し、マルチ募集v2と同じ形式で即座に募集を作成

## Botに必要な権限

### 必須
- チャンネル名編集

### 任意
- チャンネル作成（無い場合はユーザーが手動で作成）
- チャンネル削除（無くても良い）

## スラッシュコマンド

### カテゴリ登録コマンド
- 指定したカテゴリを自動募集機能に登録
- 募集日数はオプションパラメータ（2〜7日、デフォルト7日）
- Botにチャンネル作成権限があれば各種チャンネルを自動作成
- 権限がない場合は登録完了後、手動作成を促すメッセージを表示

### カテゴリ解除コマンド
- 指定したカテゴリの自動募集機能を解除
- Bot作成チャンネル（マッチング、クエスト、日時）は削除
- ユーザー指定チャンネルはBotが送信したメッセージのみ削除（チャンネルは残す）

### 日数変更コマンド
- 募集する日数を変更（2日〜7日まで変更可能）
- 未登録・デフォルト時は7日

### 参加状況確認コマンド
- 自分の登録状況（いつ、どのクエスト）を表示

### マッチング/クエストチャンネル登録コマンド
- 手動作成したマッチングチャンネルまたはクエストチャンネルを登録
- パラメータでチャンネル種別（マッチング/クエスト）を指定

### 日時チャンネル登録コマンド
- 手動作成した日時チャンネルを登録（最大5個まで同時指定可能）
- 日付の割り当てはBotが自動的に行う（不足している日時から順に割当）
- 登録後、日時チャンネルの個数が不足している場合はユーザーに報告
- days_rangeを超える分は無視（DBに登録しない）

## Discord側の構成

### カテゴリチャンネル
- ユーザーが用意

### チャンネル順序
カテゴリ内のチャンネルは以下の順序で配置：

| 順序 | チャンネル | position |
|------|-----------|----------|
| 1 | マッチングチャンネル | 0 |
| 2 | 日時チャンネル（昇順） | 1〜n |
| 3 | クエスト選択チャンネル | n+1 |

### マッチングチャンネル
- カテゴリ内に1つ用意（position 0）
- マッチング成功時にメッセージを投稿（日時、クエスト、参加者を表示）
- マルチ募集v2と同じ形式で即座に募集を作成
- 参加者全員にメンション通知

### 日時チャンネル
- カテゴリ内に任意数用意（position 1〜n）
- チャンネル名形式は「M月d日」
- 日付昇順で並べる
- セレクトBOXで1時間ごとに24時間分の選択肢を表示（最大24個同時選択可能）
- 選択はトグル式（選択完了で登録/解除）

### クエストチャンネル
- カテゴリ内に1つ用意（position n+1）
- 1クエスト1メッセージ形式で表示
- 属性指定なしクエスト：参加ボタンでトグル式登録/解除
- 6属性クエスト：属性セレクトBOX（複数選択可）で登録/解除
- master.questsの内容でメッセージを作成（sort_order降順）
- **最後のメッセージ**に「選択済みのクエスト」ボタンを配置

#### 選択済みのクエスト確認ボタン
- クエストチャンネルの最後（全クエストメッセージの後）に専用メッセージを配置
- 「📋 選択済みのクエスト」ボタンを1つ配置
- ボタン押下時、ephemeralメッセージでそのユーザーの選択情報を表示

##### 表示内容
```
📋 あなたの選択済みクエスト

🎮 クエスト名1
🎮 クエスト名2（火属性、水属性）
🎮 クエスト名3（光属性）

※ クエストを変更するには上のメッセージから操作してください
```

- クエストが選択されていない場合：「選択されているクエストはありません」と表示
- 6属性クエストは選択した属性も表示

#### ゲーム内日付の扱い
- グラブルではAM5:00に日付が変わるため、1/21チャンネルは「1/21 5:00〜1/22 4:00」を対象とする
- 選択肢の表示順は降順（夜の時間帯が先）
- 翌日4:00、翌日3:00、翌日2:00、翌日1:00、翌日0:00、当日23:00、...、当日5:00の順で表示
- 翌日分（0:00〜4:00）は「翌0:00」「翌1:00」「翌2:00」「翌3:00」「翌4:00」と表記

### チャンネル共通事項
- Bot以外は書き込み不可、編集不可
- Botにチャンネル作成権限があればBotが作成
- 権限がない場合はユーザーが手動で作成し、適切な権限を設定

## 日付ローテーション

- 内部スケジューラーの新しい区分を用意し、スケジュールとして実施
- 過去日のチャンネルでも削除しない
- 古くなった日付のチャンネルは新しい日付のチャンネル名に更新
- カテゴリ内でチャンネルを並び替え（DBも更新）

## クエスト・時間登録時の挙動

- クエストまたは時間の登録時にDBテーブルに登録
- 登録内容によって対象のデータを検索
  - クエストを変更した場合：新たに追加されたクエストを条件に検索
  - 参加時間を変更した場合：新たに追加された参加時間を条件に検索
- 他人の同一日時・同一クエストがあれば2人以上でマッチング成功

## 周期マッチング処理

### スケジュール仕様
- タスク区分：`auto_matching`
- 実行間隔：10秒
- 同時実行：不可（処理完了後に次回スケジュール登録）

### マッチング検出
- `auto_recruitment_participants`と`user_desired_quests`を結合
- 同一の(guild_id, quest_id, month, day, hour)でグルーピング
- 2人以上存在するグループを抽出
- 既存の`quest_matchings`に登録済みでないユーザーのみ対象

### 6属性クエストのグループ分け
- 属性被りがあれば別グループに分割
- 人数上限（`recruit_count`）を超えていれば別グループに分割
- 希望属性数の少ないユーザーから優先配置

## マッチング成功時の挙動

### 通知
- マッチングチャンネルにメッセージを投稿
- 日時、クエスト、参加者を表示
- 参加者全員にメンション
- 6属性クエストの場合は担当属性も表示

### 募集作成
- マッチング成立と同時にマルチ募集v2形式で即座に募集を作成
- クエストに応じた通知ロール＋参加ユーザーにメンション

### キャンセル
- 該当日時を過ぎたらキャンセル扱い

## DBテーブル仕様

### ギルド自動募集テーブル（guild_master.auto_recruitments）
- guild_id
- category_id（カテゴリID）
- matching_channel_id（マッチングチャンネルID）
- quest_channel_id（クエストチャンネルID）
- matching_channel_is_bot_created（マッチングチャンネルがBot作成か）
- quest_channel_is_bot_created（クエストチャンネルがBot作成か）
- matching_message_id（マッチングチャンネルに送信したメッセージID）
- quest_message_id（非推奨：1クエスト1メッセージのため未使用）
- days_range（何日分募集するか）
- created_at
- updated_at

### ギルド自動募集チャンネルテーブル（guild_master.auto_recruitment_channels）
- guild_id
- channel_id（チャンネルID）
- month（何月の募集か）
- day（何日の募集か）
- sort_order（並び順）
- is_bot_created（Bot作成チャンネルか）
- message_id（送信したメッセージID）
- created_at
- updated_at

### クエストメッセージテーブル（guild_master.auto_recruitment_quest_messages）
- guild_id（PK）
- quest_id（PK）
- message_id（メッセージID）
- created_at
- updated_at

### ギルドユーザー希望クエストテーブル（guild_master.user_desired_quests）
- guild_id（PK）
- user_id（PK、ユーザーID）
- quest_id（PK、クエストID）
- battle_style_id（PK、希望属性。0=属性指定なし）
- created_at
- updated_at

※ 主キーは(guild_id, user_id, quest_id, battle_style_id)
※ 同一クエストで複数属性を希望可能

### 日時募集参加者テーブル（guild_master.auto_recruitment_participants）
- guild_id
- user_id（ユーザーID）
- month（何月の募集か）
- day（何日の募集か）
- hour（何時の募集か）
- created_at
- updated_at

### マッチングテーブル（worker.quest_matchings）
- guild_id（PK）
- id（PK、UUID）
- quest_id（クエストID）
- scheduled_month（予定月）
- scheduled_day（予定日）
- scheduled_hour（予定時間）
- status（状態：active/completed/cancelled）
- recruitment_id（作成されたマルチ募集ID、募集作成後にセット）
- created_at
- updated_at

### マッチングユーザーテーブル（worker.quest_matching_users）
- guild_id（PK）
- matching_id（PK、FK→quest_matchings.id）
- user_id（PK、ユーザーID）
- battle_style_id（担当属性、6属性クエストの場合のみ）
- joined_at（参加日時）
- left_at（離脱日時、NULLなら参加中）

## 重要ルール

### 日時チャンネルの対象外条件
- Bot以外のメッセージが書かれているチャンネルは日時チャンネルとして扱わない
- 誤ってユーザーのメッセージを紛失することを防ぐため

### 年またぎの処理
- 複数年にわたる募集は想定しない
- 年末年始の調整はよしなに行う

### データ削除
- マッチング後もuser_desired_quests、auto_recruitment_participantsのレコードは残す
- 将来的に削除バッチで一括削除

### カテゴリ解除時のデータ削除
カテゴリ解除コマンド実行時、以下の順序でデータを削除：

1. Discordチャンネル/メッセージの削除
2. `quest_matching_users` - 外部キー制約のため先に削除
3. `quest_matchings` - マッチングデータ削除
4. `auto_recruitment_quest_messages` - クエストメッセージID削除
5. `auto_recruitment_channels` - 日時チャンネル情報削除
6. `auto_recruitments` - 自動募集設定削除

## エラーハンドリング

| 状況 | 対応 |
|------|------|
| チャンネルがDBにあるが実際に削除されている | エラー通知＋再作成（権限があれば） |
| チャンネルにアクセス権がない | サーバーのデフォルトチャンネルに通知（将来的にはエラーチャンネル） |
| Bot以外のメッセージがあるチャンネルを日時登録しようとした | 登録を中断＋ユーザーに報告 |
| days_rangeより多くのチャンネルを登録しようとした | 超過分は無視（DBに登録しない） |
| 日時チャンネルの個数が不足 | ユーザーに報告 |
