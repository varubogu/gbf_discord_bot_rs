# メッセージ解決

## 概要

本機能は、`message_text_id` から実際に送信するメッセージ本文を解決する共通仕様です。  
各機能（スケジュール通知、募集、設定表示など）は、本文解決を `MessageService` に委譲します。

## 目的

- メッセージ文言の管理場所を統一する
- guildごとのカスタマイズを可能にする
- DB未登録時も `locales/messages.yml` へフォールバックして機能停止を防ぐ

## 対象データソース

1. `guild_master.guild_message_texts`
2. `master.message_texts`
3. `locales/messages.yml`

## 解決処理の優先順位

`message_text_id` に対する本文解決は次の順で行います。

1. guildメッセージテキスト（`guild_message_texts`）
2. globalメッセージテキスト（`message_texts`）
3. `locales/messages.yml`
4. 1〜3のいずれにも存在しない場合は、呼び出し側でコード内フォールバックを適用（必要時のみ）
5. 4が未実装または不適用の場合はエラー

### 補足

- 1,2でDBアクセスエラーが発生した場合でも、処理は中断せず次のフォールバックへ進む
- 3は最終フォールバックであり、ここで解決できれば送信処理は継続する
- 4のコード内フォールバックは可用性維持のための最終手段であり、恒久的な文言管理先として扱わない

## コード内フォールバックの扱い

- 原則は `guild -> global -> messages.yml` で解決する。
- コード内フォールバックは、`MessageService` が `NotFound` となった場合に限って使用する。
- フォールバック文言を新規追加した場合は、同一PRまたは直近PRで `locales/messages.yml` と `MessageTextId` に移行する。

## ロケール解決

本文の言語選択は、呼び出し側から渡されたロケールを基準に行います。

- `ja` 系ロケール: 日本語本文を使用
- `ja` 以外: 英語本文を優先し、英語未定義なら日本語本文へフォールバック

### guild向け機能でのロケール

guild向けの応答は、`guild_settings.locale` を参照してロケールを決定します。  
未設定時は `ja` を使用します。

- `MessageService` の `locale=None` は内部仕様として `en` を選択する。
- そのため、guild向け機能では `locale=None` のまま `MessageService` を呼び出さない。
- 呼び出し側で `guild_settings.locale`（未設定時 `ja`）を解決して明示的に渡す。

### スケジュール通知でのロケール

スケジュール通知でも、上記と同様に `guild_settings.locale` を参照する。  
未設定時は `ja` を使用する。

## パラメータ置換

メッセージ本文内の `{{key}}` は、呼び出し側が渡したパラメータで置換します。

- 例: `こんにちは {{user_name}} さん`
- 対応: 置換対象キーが存在する場合のみ置換

## メッセージID命名・翻訳ルール

`message_text_id` は永続データ（`message_texts` / `guild_message_texts`）と連動するため、
命名規約と翻訳品質を以下で統一します。

### 命名ルール

- 同一用途・同一文言を複数IDで重複定義しない
- 生成対象が異なるだけで文言が同一の場合は、`*.shared.*` の共通IDを使用する
- 表記揺れ（例: `recruitment` と `battle_recruitment` の混在）を新規に増やさない
- `MessageTextId`、`message_text_id::keys` 定数、`locales/messages.yml` のキーはアルファベット列を一致させる
  （大文字小文字、`.` / `_` などの記号差のみ許容）

### 翻訳ルール

- `ja` は日本語文言を定義する
- `en` は英語文言を定義する
- `ja` と `en` の同一文字列定義は、固有名詞など正当な理由がある場合を除き禁止する

## エラー方針

- 1,2でデータ未存在: エラーにせずフォールバック継続
- 1,2でDBエラー: warnログを出してフォールバック継続
- 1〜3で解決不能: `MessageTextNotResolved` 相当の業務エラーとして扱う

## スケジュール機能との関係

- スケジュール機能側は、まず通知行ごとの `message_text_id` を決定する
- 本文解決（guild -> global -> `messages.yml` -> エラー）は本仕様に従う
- 詳細は [スケジュール機能](./スケジュール機能.md) を参照
