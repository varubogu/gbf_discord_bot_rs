# 募集通知

## 概要

マルチ募集に対して、出発前リマインドなどの通知を時刻実行する機能です。
通知データは `worker.notifications` と `worker.notification_rel_battle_recruitments` で管理し、実行時刻は `worker.scheduled_tasks` に保持します。

## 目的

- 募集出発前の取りこぼしを減らす
- 通知をスケジュール基盤に統合し、運用と拡張を容易にする
- 募集変更/キャンセル時の通知整合性を保証する

## 基本仕様

- 既定通知: 出発時刻の5分前
- メッセージテンプレート: `RECRUIT_DEPARTURE_REMINDER`
- 通知送信対象: 募集参加者および関連メンション対象
- 実行主体: SchedulerManager（10秒周期）

## データモデル

### `worker.scheduled_tasks`

- `task_type = Notification`
- `schedule_datetime` が通知実行時刻
- `is_executed` で実行状態を管理

### `worker.notifications`

- `task_id` で `scheduled_tasks.id` を参照
- `guild_id` / `channel_id` / `message_text_id` を保持
- `is_sent` で送信済み状態を管理

### `worker.notification_rel_battle_recruitments`

- 募集レコードと通知レコードの関連を保持
- 募集変更時の再生成対象特定に使用

## 処理フロー

### 募集作成時

1. 募集を保存
2. 出発時刻から通知時刻を計算（-5分）
3. `scheduled_tasks`（Notification）を作成
4. `notifications` を作成
5. `notification_rel_battle_recruitments` を作成

### 募集変更時

1. 既存関連から通知を特定
2. 既存通知（関連・通知本体・タスク）を削除
3. 新しい出発時刻で通知を再生成

### 募集キャンセル時

1. 関連する通知を削除
2. 実行待ちタスクの残骸を残さない

## エラーハンドリング

- 通知作成失敗: 募集作成処理と同一トランザクションでロールバック
- 通知更新失敗: 更新全体をロールバック
- 送信失敗: ログ出力し、再試行方針に従って再実行可能な状態を維持

## テスト観点

- 通知時刻計算（境界: 日跨ぎ、同時刻付近）
- 募集変更時の古い通知削除と再作成
- キャンセル時の通知一括削除
- 二重送信防止（`is_sent` / `is_executed`）

## 運用観点

- 通知成功率と遅延の監視
- 通知未実行件数の監視
- メッセージテンプレート欠損時のフォールバック確認
