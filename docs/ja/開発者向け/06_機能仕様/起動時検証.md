# 起動時バリデーション機能

## 概要

アプリケーション起動時に必要な環境変数とファイルの存在をチェックし、エラーがあれば分かりやすく表示する機能です。これにより、設定ミスによる実行時エラーを事前に防ぎ、開発者とオペレータの体験を向上させます。

## 目的

- **早期エラー検出**: 起動直後に設定不備を検出し、実行時エラーを防ぐ
- **明確なフィードバック**: どの設定項目に問題があるかを一目で把握できる
- **運用効率化**: トラブルシューティング時間を短縮
- **開発体験向上**: 初回セットアップ時の試行錯誤を削減

## 機能要件

### 1. 起動時環境チェック

アプリケーション起動時（データベース接続前）に以下をチェック：

#### チェック項目

**必須環境変数**:
- `DISCORD_TOKEN` - Discord Bot トークン
- `BOT_ADMIN_SERVER_ID` - Bot管理者専用サーバーID
- `DB_HOST` - データベースホスト名
- `DB_PORT` - データベースポート番号
- `DB_NAME` - データベース名
- `GUILD_DB_USER` - Guildロールユーザー名
- `GUILD_DB_PASSWORD` - Guildロールパスワード
- `SYSTEM_DB_USER` - Systemロールユーザー名
- `SYSTEM_DB_PASSWORD` - Systemロールパスワード
- `GLOBAL_DB_USER` - Globalロールユーザー名
- `GLOBAL_DB_PASSWORD` - Globalロールパスワード
- `ADMIN_DB_USER` - Adminロールユーザー名（マイグレーション用）
- `ADMIN_DB_PASSWORD` - Adminロールパスワード（マイグレーション用）
- `GUILD_SPREADSHEET_TEMPLATE_URL` - ギルド初期設定メッセージで表示するテンプレートURL

**任意環境変数**:
- `GLOBAL_SPREADSHEET_ID` - グローバルスプレッドシートID（スプレッドシート機能使用時のみ必須）
- `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` - Googleサービスアカウントキーファイルパス（スプレッドシート機能使用時のみ必須）

**ファイル存在チェック**:
- `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` で指定されたファイルの存在確認
- ファイルが存在する場合、JSON形式として読み込み可能かチェック

### 3. 実行時エラーの詳細表示

データベース接続、JSON パース等のエラー時に詳細情報を表示：

```

Constructed URL: postgresql://guild_user:***@localhost:5432/invalid_db
Error Details: Connection refused (SQLSTATE: 08001)

Possible Causes:
  - PostgreSQL server is not running
  - Database name is incorrect
  - Host or port is unreachable
  - Authentication failed

💡 Troubleshooting:
  1. Check PostgreSQL server status: sudo systemctl status postgresql
  2. Verify DB connection parameters: DB_HOST, DB_PORT, DB_NAME
  3. Verify role credentials: GUILD_DB_USER, GUILD_DB_PASSWORD
  4. Test connection: psql "postgresql://guild_user:password@localhost:5432/gbf_bot_db"
```

## 非機能要件

### パフォーマンス
- 環境チェックは1秒以内に完了すること
- ファイル読み込みは非同期で実行

### ユーザビリティ
- エラーメッセージは日本語で表示
- 視覚的に分かりやすい記号（✅❌⚠️💡）を使用
- 長い値（トークン等）は先頭・末尾のみ表示（例: `dMzY...xy2A`）

### セキュリティ
- 機密情報（トークン、パスワード）はマスクして表示
- ログファイルには機密情報を出力しない

## アーキテクチャ設計

### コンポーネント構成

```
main.rs
  ↓
StartupValidator (新規作成)
  ↓
EnvValidator (新規作成)
  ├─ check_required_env_vars()
  ├─ check_optional_env_vars()
  └─ check_file_validation()
```

### 起動処理におけるDBアクセス方針

- 起動時バリデーション自体は環境変数・ファイル検証に限定し、旧ラッパーへ依存しない。
- DB由来の環境値読込が必要な場合は、`src/infrastructure/database/session/DatabaseSession`（互換用途）または `AppState` 管理接続を利用する。
- `models_database` / `db_compat` を直接利用しない。
- RLSなどのセッション文脈SQLは `src/infrastructure/database/session` に集約する。

### クラス設計

#### StartupValidator

```rust
/// 起動時バリデーター
pub struct StartupValidator {
    results: Vec<ValidationResult>,
}

impl StartupValidator {
    pub fn new() -> Self;

    /// 全チェックを実行
    pub async fn validate_all() -> Result<(), StartupError>;

    /// 結果を表示
    pub fn display_results(&self);

    /// バリデーション成功か
    pub fn is_valid(&self) -> bool;
}
```

#### ValidationResult

```rust
/// バリデーション結果
pub struct ValidationResult {
    pub category: ValidationCategory,
    pub item_name: String,
    pub status: ValidationStatus,
    pub message: Option<String>,
    pub help_text: Option<String>,
}

pub enum ValidationCategory {
    RequiredEnvVar,
    OptionalEnvVar,
    FileValidation,
    DatabaseConnection,
}

pub enum ValidationStatus {
    Ok,
    Warning,
    Error,
}
```

#### EnvValidator

```rust
/// 環境変数バリデーター
pub struct EnvValidator;

impl EnvValidator {
    /// 必須環境変数をチェック
    pub fn check_required_vars() -> Vec<ValidationResult>;

    /// 任意環境変数をチェック
    pub fn check_optional_vars() -> Vec<ValidationResult>;

    /// ファイル存在・内容をチェック
    pub async fn check_files() -> Vec<ValidationResult>;

    /// JSON ファイルをバリデート
    pub async fn validate_json_file(path: &str) -> Result<(), String>;
}
```

#### ErrorFormatter (新規作成)

```rust
/// エラーフォーマッター
pub struct ErrorFormatter;

impl ErrorFormatter {
    /// データベースエラーをフォーマット
    pub fn format_db_error(err: &DbErr, db_url: &str) -> String;

    /// JSON パースエラーをフォーマット
    pub fn format_json_error(err: &serde_json::Error, file_path: &str) -> String;

    /// 一般的なエラーをフォーマット
    pub fn format_generic_error(err: &dyn std::error::Error, context: &str) -> String;
}
```

### エラー型定義

```rust
/// 起動時エラー
#[derive(Error, Debug)]
pub enum StartupError {
    #[error("Required environment variable not set: {var_name}")]
    MissingRequiredEnvVar { var_name: String },

    #[error("File not found: {file_path} (specified in {env_var})")]
    FileNotFound { file_path: String, env_var: String },

    #[error("Invalid JSON in file: {file_path}\n{details}")]
    InvalidJson { file_path: String, details: String },

    #[error("Database connection failed: {details}")]
    DatabaseConnectionFailed { details: String },

    #[error("Multiple validation errors occurred")]
    MultipleErrors { errors: Vec<String> },
}
```

## 実装フロー

### 起動シーケンス

```
1. main()
   ↓
2. StartupValidator::validate_all()
   ↓
3. EnvValidator::check_required_vars()
   ├─ DISCORD_TOKEN
   ├─ BOT_ADMIN_SERVER_ID
   ├─ DB_HOST
   ├─ DB_PORT
   ├─ DB_NAME
   ├─ GUILD_DB_USER
   ├─ GUILD_DB_PASSWORD
   ├─ SYSTEM_DB_USER
   ├─ SYSTEM_DB_PASSWORD
   ├─ GLOBAL_DB_USER
   ├─ GLOBAL_DB_PASSWORD
   ├─ ADMIN_DB_USER
   ├─ ADMIN_DB_PASSWORD
   └─ GUILD_SPREADSHEET_TEMPLATE_URL
   ↓
4. EnvValidator::check_optional_vars()
   ├─ GLOBAL_SPREADSHEET_ID
   └─ GOOGLE_SERVICE_ACCOUNT_KEY_FILE
   ↓
5. EnvValidator::check_files()
   └─ Service Account Key JSON
   ↓
6. StartupValidator::display_results()
   ↓
7. StartupValidator::is_valid() ?
   ├─ Yes → Continue to database initialization
   └─ No → Exit with error code 1
```

### エラーハンドリングフロー

```
Runtime Error Occurs
   ↓
Capture Error with Context
   ↓
ErrorFormatter::format_*_error()
   ↓
Display Formatted Error
   ↓
Exit with appropriate code
```

## 制約事項

### 現在の制約

- 環境変数チェックは同期処理（高速なため問題なし）
- ファイルチェックは非同期処理（大容量ファイル対応）
- データベース接続チェックは実施しない（起動時間への影響を避けるため）

### 将来的な拡張

- データベース接続テスト機能の追加（オプション）
- Discord API接続テスト（オプション）
- 設定ファイルの妥当性チェック（.envファイルの構文チェック）

## テスト戦略

### 単体テスト

- `EnvValidator::check_required_vars()` - 環境変数の有無チェック
- `EnvValidator::validate_json_file()` - JSON形式チェック
- `ErrorFormatter::format_*_error()` - エラーメッセージ生成

### 統合テスト

- 環境変数未設定時の挙動
- 不正なJSON形式ファイル読み込み時の挙動
- 全チェック成功時の表示確認

### 手動テスト

- 実際の環境での起動確認
- エラーメッセージの可読性確認
- トラブルシューティング手順の有効性確認
