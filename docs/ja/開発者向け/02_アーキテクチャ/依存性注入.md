# 依存性注入（DI）

## 目的

層の責務を守りながら、変更に強くテストしやすい構造を維持するために、依存関係を外部から注入します。

## 基本方針

- 依存関係は `AppState` に集約し、必要な場所へ必要な分だけ渡す
- DB接続は `AppState` が管理し、各層が勝手に新規接続しない
- ServiceはRepository traitに依存し、具象アダプターには依存しない
- 依存を隠すためのグローバル変数は使わない

## 構成ルート（Composition Root）ルール

- DB具象実装（`SeaOrm*Repository` など）を扱うのは構成ルートのみ。
- 主な配線点は `src/di/repositories.rs`。
- DI以外の層では `src/repository/**` のtraitを使う。

## 依存関係の渡し方（実務ルール）

### events（プレゼンテーション層）

- 入力検証を行い、Facadeに渡すパラメータを組み立てる
- `AppState` からFacade作成に必要な依存を取り出す（必要最小限）

### facades（トランザクション境界）

- Serviceを組み合わせてユースケースを構成する
- トランザクションを開始し、Serviceへ渡す

### services / repository

- ServiceはRepository trait経由で永続化する
- Repository portは契約定義のみを持ち、永続化詳細はinfrastructureアダプターへ隔離する

## テストの差し替え

- 単体テストでは外部I/O（Discord/DB）をテストダブルで差し替える
- Trait + `mockall` を基本とし、差し替えは必要最小限にする

## 具象アダプターの扱い

- `SeaOrm*Repository` などの具象型を扱う場所は `src/di/repositories.rs` に限定する。
- DI以外のコードは `src/repository/**` のtraitのみを参照する。
- 依存配線時にのみ `src/infrastructure/database/repositories/**` の実装型を使用する。
