# コーディング規約

## 最低限のルール

- コメント/ドキュメント/エラーメッセージは日本語
- `unwrap()` は本番コードで禁止（回復不能のみ `panic!()` を検討）
- 命名: 型 `PascalCase`、関数/変数 `snake_case`、定数 `SCREAMING_SNAKE_CASE`
- 動的ディスパッチ（dyn Trait）は禁止。静的ディスパッチ（ジェネリクスによる型パラメータ）を使用すること。
- ユーザー向け表示文字列（メッセージ本文、Embed、ボタン/セレクト/モーダルのラベル・プレースホルダー、インタラクション応答）は `locales/messages.yml` に定義し、`MessageTextId` / `MessageService` 経由で取得する。Rustコードへの直書きは禁止。

## マスターテーブルのIDはenumで定義する

マスターテーブルの ID カラムが **コードで管理された固定値セット**（ユーザーが自由に入力するのではなく、コードベースで値を管理するもの）の場合、そのIDをRustのenumとして定義する。

ルール:
- そのテーブルのエンティティファイル `src/models/entities/<schema>/<table>.rs` 内にenumを定義する
- `as_i32(&self) -> i32` と `from_i32(value: i32) -> Option<Self>` ヘルパーを実装する
- enum の値は常に実際のDBマスターレコードと同期を保つこと
- これらのIDに対して `const` 定数を単独で定義しない — enum バリアントを使うこと

例: `src/models/entities/worker/scheduled_tasks.rs` の `ScheduledTaskType`
例: `src/models/entities/master/channel_types.rs` の `GuildChannelType`

## 守ると楽になること

- 1つの関数は短く、責務は1つに絞る（読みやすさは保守コストに直結する）
- `clone()` を雑に増やさない（必要なら理由を説明できる状態にする）
- `Arc<T>` は「共有が必要なところだけ」に限定する
