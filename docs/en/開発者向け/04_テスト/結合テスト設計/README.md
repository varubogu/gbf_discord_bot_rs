# 結合テスト設計（機能別）

このフォルダには、機能ごとの結合テスト設計（前提データ、ケース一覧、期待結果、クリーンアップ方式など）を置きます。

## 置く理由

- テストコードだけだと「前提」「期待結果」「片付け方」が読み取りづらくなる
- 実DBテストは失敗時の復旧が面倒になりやすいので、設計書で手順を固定する

## テンプレート（例）

```markdown
# {機能名} 結合テスト設計

## 対象ユースケース

- 何を検証するか（Facade名、操作名）

## 前提データ

- 必要なギルド設定/クエスト/チャンネル等

## 正常系

- 1-1: 入力 → 期待結果

## 異常系

- 2-1: 前提不足
- 2-2: 権限不足

## クリーンアップ

- 削除するテーブル/条件（guild_id等）

## 実行コマンド

- cargo test {絞り込み}
```
