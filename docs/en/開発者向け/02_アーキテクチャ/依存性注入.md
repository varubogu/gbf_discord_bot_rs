# 依存性注入（DI）

## 目的

層の責務を守りつつ、変更に強く・テストしやすい構造にするために依存関係を外から渡します。

## 基本方針

- 依存関係は `AppState` に集約し、必要なものを必要な場所へ渡す
- DB接続は `AppState` が管理し、各層が勝手に新規接続しない
- 「便利だからグローバル変数」はしない（依存が見えなくなり事故が起きる）

## 依存関係の渡し方（実務ルール）

### events（プレゼンテーション層）

- 入力検証を行い、Facadeに渡すパラメータを組み立てる
- `AppState` からFacade作成に必要な依存を取り出す（必要最小限）

### facades（トランザクション境界）

- サービスを組み合わせてユースケースを作る
- トランザクションを開始し、Serviceへ渡す

### services / repository

- Serviceは Repository を通じて永続化を行う
- Repository は「DBの読み書き」に集中し、業務判断を持たない

## テストのための差し替え

- 単体テストでは、外部I/O（Discord/DB）をテストダブルで差し替える
- Trait + `mockall` による差し替えを基本とする（必要最小限でよい）
