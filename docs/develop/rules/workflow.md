# ワークフロールール

## 基本方針

機能の追加・修正・削除において、以下の原則を遵守してください：

1. **包括性**: コード変更は必ずドキュメントとテストの更新を含む
2. **トレーサビリティ**: 変更の影響範囲を明確にし、関連するすべての成果物を更新
3. **品質保証**: 各ワークフローで適切なテスト戦略を実行

## 追加ワークフロー

新機能やコンポーネントを追加する際の手順：

### 1. 設計・計画フェーズ

- [ ] 要件定義の明確化
- [ ] アーキテクチャ設計書の更新
- [ ] 影響範囲の分析

### 2. 実装フェーズ

- [ ] コード実装（クリーンアーキテクチャ遵守）
- [ ] 単体テスト作成
- [ ] 統合テスト作成

### 3. ドキュメント更新フェーズ

- [ ] API仕様書更新
- [ ] ユーザー向けドキュメント更新
- [ ] 設計書更新

### 4. 検証・デプロイフェーズ

- [ ] コードレビュー実施
- [ ] システムテスト実行
- [ ] パフォーマンステスト実行

### 追加時の注意事項

#### 層別実装順序

1. **Infrastructure層**: データベーステーブル、外部API連携
2. **Repository層**: データアクセス実装
3. **Service層**: ビジネスロジック実装
4. **Facade層**: サービス協調とトランザクション管理
5. **Presentation層**: Discord イベント・コマンド実装

#### 必須テスト項目

- **単体テスト**: 各層のロジック検証
- **統合テスト**: 層間連携の動作検証
- **システムテスト**: エンドツーエンドの動作検証

## 修正ワークフロー

既存機能の変更・バグ修正を行う際の手順：

### 1. 問題分析フェーズ

- [ ] 問題の特定と根本原因分析
- [ ] 影響範囲の調査
- [ ] 修正方針の策定

### 2. 修正実装フェーズ

- [ ] コード修正の実装
- [ ] 既存テストの更新・追加
- [ ] リグレッションテストの実行

### 3. ドキュメント更新フェーズ

- [ ] 変更内容のドキュメント反映
- [ ] CHANGELOG更新
- [ ] 必要に応じてユーザー向け説明書更新

### 4. 検証フェーズ

- [ ] 修正内容の動作確認
- [ ] 既存機能への影響確認
- [ ] パフォーマンス影響評価

### 修正時の注意事項

#### 変更の影響範囲分析

```
修正対象の特定
    ↓
依存関係の調査
    ↓
テストケースの洗い出し
    ↓
ドキュメント更新箇所の特定
```

#### 必須検証項目

- **回帰テスト**: 既存機能が正常に動作することを確認
- **パフォーマンステスト**: 修正による性能劣化がないことを確認
- **セキュリティテスト**: セキュリティ面での影響がないことを確認

## 削除ワークフロー

機能やコンポーネントを削除する際の手順：

### 1. 削除準備フェーズ

- [ ] 削除対象の特定
- [ ] 依存関係の調査
- [ ] 削除の影響範囲分析
- [ ] 削除計画の策定

### 2. 段階的削除フェーズ

- [ ] 非推奨マーキング（Deprecated）
- [ ] 代替手段の提供
- [ ] ユーザーへの事前通知
- [ ] 段階的な機能停止

### 3. 実削除フェーズ

- [ ] コードの削除
- [ ] 関連テストの削除・更新
- [ ] データベーススキーマの変更（必要に応じて）
- [ ] 設定ファイルのクリーンアップ

### 4. 後処理フェーズ

- [ ] ドキュメントからの削除
- [ ] CHANGELOG更新
- [ ] 残存する参照の確認・清理

### 削除時の注意事項

#### 安全な削除手順

```
依存関係調査
    ↓
段階的削除計画策定
    ↓
非推奨マーキング
    ↓
ユーザー通知
    ↓
実削除実行
    ↓
クリーンアップ
```

#### 削除前必須チェック

- **依存性確認**: 他の機能からの参照がないことを確認
- **データ保全**: 重要なデータが失われないことを確認
- **ロールバック計画**: 問題発生時の復旧手順を準備

## 共通ガイドライン

### 各ワークフローで必須となる作業

#### コード品質

- [ ] Clippy警告の解消
- [ ] フォーマッターの適用
- [ ] コードレビューの実施

#### テスト品質

- [ ] テストカバレッジの確認
- [ ] テストケースの妥当性検証
- [ ] テストデータの整備

#### ドキュメント品質

- [ ] 技術ドキュメントの正確性確認
- [ ] ユーザードキュメントの更新
- [ ] サンプルコードの動作確認

### バージョン管理

- **feature/**: 新機能追加
- **fix/**: バグ修正
- **refactor/**: リファクタリング
- **remove/**: 機能削除
- **docs/**: ドキュメント更新のみ

### リリース手順

1. 開発ブランチでの作業完了
2. プルリクエスト作成
3. コードレビュー
4. CI/CD パイプラインの実行
5. マージとデプロイ
