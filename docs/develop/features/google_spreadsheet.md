# Googleスプレッドシート連携機能

## 概要

Googleスプレッドシートを使用してPostgreSQLデータベースとの双方向データ同期を実現する機能です。マスターデータやギルド固有設定をスプレッドシートで管理し、Botと同期できます。

## 目的

- **データ管理の簡易化**: SQLを書かずにスプレッドシートでデータ管理
- **非エンジニアでも編集可能**: 表計算ソフトの操作だけでBotの設定変更が可能
- **バックアップとバージョン管理**: Googleドライブの版履歴機能を活用
- **データの可視化**: スプレッドシートでデータを視覚的に確認・編集

## 機能分類

本機能は2種類のスプレッドシート連携を提供します：

### 1. グローバルスプレッドシート連携

**用途**: 全ギルド共通のマスターデータ管理

- **対象データ**: battle_types、quests、elements、messagesなど
- **実行権限**: Bot管理者専用サーバーのみ
- **影響範囲**: 全ギルド
- **コマンド**:
  - `/gspread_global_load` - スプレッドシート → PostgreSQL
  - `/gspread_global_push` - PostgreSQL → スプレッドシート

### 2. ギルドスプレッドシート連携

**用途**: ギルド固有のカスタムデータ管理

- **対象データ**: guild_environments、guild_messages、guild_event_schedulesなど
- **実行権限**: gbf_bot_controlロール保持者
- **影響範囲**: 実行したギルドのみ
- **コマンド**:
  - `/gspread_load` - スプレッドシート → PostgreSQL
  - `/gspread_push` - PostgreSQL → スプレッドシート

## 主要ユースケース

### ユースケース1: クエスト情報の一括登録

**シナリオ**: 新しいマルチバトルクエストが追加された

1. Bot管理者がグローバルスプレッドシートの「クエスト情報」シートを編集
2. 新クエストの情報（名前、募集人数、デフォルト戦術）を追加
3. `/gspread_global_load`コマンドを実行
4. 全ギルドで新クエストが利用可能になる

### ユースケース2: ギルド固有のイベントスケジュール設定

**シナリオ**: 特定ギルドが独自のイベント通知スケジュールを設定したい

1. ギルド管理者がギルド固有スプレッドシートの「ギルドイベントスケジュール」シートを編集
2. 独自の通知タイミングや通知先チャンネルを設定
3. `/gspread_load`コマンドを実行
4. 当該ギルドのみでカスタムスケジュールが有効になる

### ユースケース3: メッセージテンプレートのカスタマイズ

**シナリオ**: ギルドの雰囲気に合わせてBotのメッセージを変更したい

1. ギルド管理者がギルド固有スプレッドシートの「ギルドメッセージ定義」シートを編集
2. 特定メッセージIDの文言を変更
3. `/gspread_load`コマンドを実行
4. 当該ギルドのみでカスタムメッセージが表示される

### ユースケース4: データのバックアップ

**シナリオ**: 現在のデータベース状態をスプレッドシートに保存したい

1. `/gspread_global_push`または`/gspread_push`コマンドを実行
2. PostgreSQLのデータがスプレッドシートに書き込まれる
3. Googleドライブの版履歴機能でバックアップが保存される

## スプレッドシート構成

### 「テーブル名」シート（メタ情報）

すべてのスプレッドシートは「テーブル名」という特殊シートを持ち、どのテーブルを同期するかを定義します。

| 列名 | 説明 | 値の例 |
|-----|------|-------|
| table_name_jp | テーブル日本語名（シート名） | "クエスト情報" |
| table_name_en | テーブル物理名（PostgreSQL） | "quests" |
| table_io | 処理方向 | "in", "out", "in,out" |
| table_type | テーブルタイプ | "reference", "transaction", "history" |

**table_io の意味**:
- `in` - スプレッドシート → PostgreSQL（読み込み専用）
- `out` - PostgreSQL → スプレッドシート（書き込み専用）
- `in,out` - 双方向（読み書き両対応）

### 各テーブルシート

テーブルごとに1シートを作成します。

**シート構造**:
- **1行目**: カラム物理名（PostgreSQLと完全一致）
- **2行目**: カラム日本語名（人間が理解しやすくするため、プログラムでは未使用）
- **3行目以降**: データ行

**例: questsシート**

| target_id | recruit_count | quest_name | use_battle_type | default_battle_type |
|-----------|--------------|-----------|----------------|-------------------|
| クエストID | 募集人数 | クエスト名 | 使用可能戦術 | デフォルト戦術 |
| 1 | 30 | プロトバハムートHL | 1,2,3 | 1 |
| 2 | 18 | アルティメットバハムートHL | 1,2 | 2 |

## データ同期の優先順位

ギルド固有データとグローバルデータが両方存在する場合、**ギルド固有データが優先**されます。

```
データ参照時の優先順位:
1. ギルド固有テーブル（guild_*）を検索
2. 存在しない場合、グローバルテーブル（*）を検索
3. どちらにも存在しない場合、デフォルト値またはエラー
```

**例: メッセージ取得**
- ギルドAが`guild_messages`に`welcome_message`を定義 → ギルドA独自のメッセージを表示
- ギルドBが定義していない → グローバルの`messages`の`welcome_message`を表示

## 権限管理

### グローバルスプレッドシート

- **実行可能者**: Bot管理者専用サーバーの参加者
- **環境変数**: `BOT_ADMIN_SERVER_ID`で指定されたサーバー
- **レスポンス**: 通常メッセージ（他の管理者も確認可能）

### ギルドスプレッドシート

- **実行可能者**: gbf_bot_controlロール保持者
- **レスポンス**: 通常メッセージ（デフォルト）

## 認証方式

Google Cloud Platform（GCP）のサービスアカウントを使用したOAuth2認証を採用します。

**必要な環境変数**:
```bash
GOOGLE_SERVICE_ACCOUNT_KEY_FILE=/path/to/service-account-key.json
```

**必要なGoogleスコープ**:
- `https://www.googleapis.com/auth/spreadsheets`

## エラーハンドリング

### エラー時の動作

- **スプレッドシート接続失敗**: コマンド実行を中断、ユーザーにエラーメッセージ表示
- **データ変換エラー**: エラー行をスキップし、ログに記録、処理は継続
- **データベースエラー**: トランザクションをロールバック、全変更を破棄

### エラーメッセージ例

```
❌ エラー: このコマンドはBot管理者専用サーバーでのみ実行可能です

❌ エラー: Googleスプレッドシートへの接続に失敗しました
詳細はログを確認してください

❌ エラー: データ変換中にエラーが発生しました
- questsテーブル 5行目: recruit_count は数値である必要があります
```

## パフォーマンス考慮事項

- **バルクインサート**: 1行ずつではなく一括でデータベースに投入
- **並行処理**: 独立したテーブルは並行で処理
- **トランザクション**: 全テーブルの更新を1トランザクションで実行（全成功or全失敗）

## セキュリティ

- **サービスアカウントキー**: ファイルシステム権限で保護（600推奨）
- **スプレッドシートURL**: 環境変数で管理、ログに出力しない
- **SQLインジェクション**: SeaORMのパラメータバインディングで防止
- **機密情報のマスキング**: エラーログに機密情報を含めない

## 制約事項

### 現在の制約

- **全件同期のみ**: 差分更新は未対応（将来対応予定）
- **リアルタイム同期なし**: コマンド実行時のみ同期
- **スプレッドシート数制限**: グローバル1つ、ギルドごとに1つ

### 推奨される運用

- **小規模データ**: 数千行程度までのデータを推奨
- **定期的なバックアップ**: `/gspread_push`で定期的にスプレッドシートに書き出し
- **変更履歴の確認**: Googleドライブの版履歴機能を活用

## FAQ

### Q1: グローバルスプレッドシートとギルドスプレッドシートの使い分けは？

**A**: 全ギルド共通のマスターデータ（クエスト情報、戦術定義など）はグローバルスプレッドシート、ギルド独自のカスタマイズ（メッセージ文言、イベントスケジュールなど）はギルドスプレッドシートを使用します。

### Q2: データ変換エラーが発生した行はどうなる？

**A**: エラー行はスキップされ、ログに記録されます。他の正常な行は処理されます。ユーザーにはエラー発生行数とエラー内容が表示されます。

### Q3: トランザクションはどのタイミングでコミットされる？

**A**: 全テーブルのデータ投入が成功した時点でコミットされます。途中でエラーが発生した場合、全変更がロールバックされます。

### Q4: スプレッドシートURLはどこで管理する？

**A**: グローバルスプレッドシートは環境変数で管理します。ギルドスプレッドシートは環境変数またはデータベース（guild_environmentsテーブル）で管理できます。

### Q5: 既存データは上書きされる？

**A**: はい。`/gspread_load`実行時、該当テーブルのデータは一度削除され、スプレッドシートのデータで置き換えられます（TRUNCATE + INSERT）。

### Q6: 複数人が同時に実行したらどうなる？

**A**: トランザクションにより排他制御されますが、コマンドの実行順序により最後の実行結果が反映されます。運用ルールで同時実行を避けることを推奨します。
