# マルチバトル募集オートマッチング機能 設計書

## 概要



ユーザーが希望するクエストと参加可能時間を事前登録し、条件が一致する他のユーザーと自動的にマッチングして募集を行う機能です。カテゴリチャンネルを活用し、日付ごとのチャンネルで参加時間を、クエストチャンネルで希望クエストを管理します。

## 機能の流れ

1. ユーザーがDiscord上でカテゴリを作成
2. カテゴリ登録コマンドで自動募集機能を有効化
3. Botが各種チャンネル（マッチング、クエスト、日時）を作成
4. 必要に応じて日数変更コマンドで募集期間を調整
5. ユーザーがクエストチャンネルで希望クエストを登録、日時チャンネルで参加可能時間を登録（順不同）
6. 2人以上が同じ日時・同じクエストを希望した場合、マッチング成功
7. マッチング済みチャンネルに通知し、参加者にどのクエストを行うか投票を求める
8. クエストが決定したらマルチ募集v2と同じ形式で募集を作成

## Botに必要な権限

### 必須
- チャンネル名編集

### 任意
- チャンネル作成（無い場合はユーザーが手動で作成）
- チャンネル削除（無くても良い）

## スラッシュコマンド

### カテゴリ登録コマンド
- 指定したカテゴリを自動募集機能に登録
- Botにチャンネル作成権限があれば各種チャンネルを自動作成
- 権限がない場合は登録完了後、手動作成を促すメッセージを表示

### カテゴリ解除コマンド
- 指定したカテゴリの自動募集機能を解除

### 日数変更コマンド
- 募集する日数を変更（2日〜7日まで変更可能）
- 未登録・デフォルト時は7日

### 参加状況確認コマンド
- 自分の登録状況（いつ、どのクエスト）を表示

### マッチング/クエストチャンネル登録コマンド
- 手動作成したマッチングチャンネルまたはクエストチャンネルを登録
- パラメータでチャンネル種別（マッチング/クエスト）を指定

### 日時チャンネル登録コマンド
- 手動作成した日時チャンネルを登録（最大5個まで同時指定可能）
- 日付の割り当てはBotが自動的に行う（不足している日時から順に割当）
- 登録後、日時チャンネルの個数が不足している場合はユーザーに報告
- days_rangeを超える分は無視（DBに登録しない）

## Discord側の構成

### カテゴリチャンネル
- ユーザーが用意

### マッチング済みチャンネル
- カテゴリ内に1つ用意
- マッチング成功時にメッセージを投稿（日時、クエスト候補、参加者を表示）
- セレクトBOXでどのクエストにするか投票
- 「何でも良い」の選択肢あり
- クエスト決定後、マルチ募集v2と同じ形式で募集を作成

### クエストチャンネル
- カテゴリ内に1つ用意
- セレクトBOXでクエストを選択
- master.questsの内容で選択肢を作成
- クエスト数が25個を超える場合は複数のセレクトBOXに分割（クエスト表示順、ID順の降順）
- 選択はトグル式（選択完了で登録/解除）

### 日時チャンネル
- カテゴリ内に任意数用意
- チャンネル名形式は「MM-dd(曜日)」
- 日付昇順で並べる
- セレクトBOXで1時間ごとに24時間分の選択肢を表示（最大24個同時選択可能）
- 選択はトグル式（選択完了で登録/解除）

### チャンネル共通事項
- Bot以外は書き込み不可、編集不可
- Botにチャンネル作成権限があればBotが作成
- 権限がない場合はユーザーが手動で作成し、適切な権限を設定

## 日付ローテーション

- 内部スケジューラーの新しい区分を用意し、スケジュールとして実施
- 過去日のチャンネルでも削除しない
- 古くなった日付のチャンネルは新しい日付のチャンネル名に更新
- カテゴリ内でチャンネルを並び替え（DBも更新）

## クエスト・時間登録時の挙動

- クエストまたは時間の登録時にDBテーブルに登録
- 登録内容によって対象のデータを検索
  - クエストを変更した場合：新たに追加されたクエストを条件に検索
  - 参加時間を変更した場合：新たに追加された参加時間を条件に検索
- 他人の同一日時・同一クエストがあれば2人以上でマッチング成功

## マッチング成功時の挙動

### 通知
- マッチング済みチャンネルにメッセージを投稿
- 日時、クエスト候補、参加者を表示
- 3人以上マッチした場合は既存メッセージを編集して参加者を追加

### 投票
- セレクトBOXでどのクエストにするか選択
- 「何でも良い」の選択肢あり
- 「何でも良い」を選んだ人は最終決定権なし
- 全員が「何でも良い」の場合はランダムで決定
- 同数投票の場合は全員に再投票を求める（元メッセージに返信する形で新しいメッセージを投稿）

### タイムアウト・キャンセル
- 該当日時を過ぎたらキャンセル
- 何も入力しなければキャンセル扱い

### 募集作成
- クエスト決定後、Botがマルチ募集v2と同じ形式で募集を作成（定期募集処理を参考）

## DBテーブル仕様

### ギルド自動募集テーブル（guild_master.auto_recruitments）
- guild_id
- category_id（カテゴリID）
- days_range（何日分募集するか）
- created_at
- updated_at

### ギルド自動募集チャンネルテーブル（guild_master.auto_recruitment_channels）
- guild_id
- channel_id（チャンネルID）
- month（何月の募集か）
- day（何日の募集か）
- created_at
- updated_at

### ギルドユーザー希望クエストテーブル（guild_master.user_desired_quests）
- guild_id
- user_id（ユーザーID）
- quest_id（クエストID）
- created_at
- updated_at

### 日時募集参加者テーブル（guild_master.auto_recruitment_participants）
- guild_id
- user_id（ユーザーID）
- month（何月の募集か）
- day（何日の募集か）
- hour（何時の募集か）
- created_at
- updated_at

### マッチング済みチャンネルテーブル（worker.matched_recruitment_channels）
- guild_id
- channel_id（チャンネルID）
- message_id（メッセージID）
- month（何月の募集か）
- day（何日の募集か）
- hour（何時の募集か）
- quest_id（決定したクエストID、未決定ならNULL）
- created_at
- updated_at

### マッチング投票テーブル（worker.matched_recruitment_votes）
- guild_id
- matched_channel_id（matched_recruitment_channelsへの参照）
- message_id
- user_id
- quest_id（NULLなら「何でも良い」）
- created_at
- updated_at

## 重要ルール

### 日時チャンネルの対象外条件
- Bot以外のメッセージが書かれているチャンネルは日時チャンネルとして扱わない
- 誤ってユーザーのメッセージを紛失することを防ぐため

### 年またぎの処理
- 複数年にわたる募集は想定しない
- 年末年始の調整はよしなに行う

### データ削除
- マッチング後もuser_desired_quests、auto_recruitment_participantsのレコードは残す
- 将来的に削除バッチで一括削除

## エラーハンドリング

| 状況 | 対応 |
|------|------|
| チャンネルがDBにあるが実際に削除されている | エラー通知＋再作成（権限があれば） |
| チャンネルにアクセス権がない | サーバーのデフォルトチャンネルに通知（将来的にはエラーチャンネル） |
| Bot以外のメッセージがあるチャンネルを日時登録しようとした | 登録を中断＋ユーザーに報告 |
| days_rangeより多くのチャンネルを登録しようとした | 超過分は無視（DBに登録しない） |
| 日時チャンネルの個数が不足 | ユーザーに報告 |
