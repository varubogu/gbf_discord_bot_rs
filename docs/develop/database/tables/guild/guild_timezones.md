# ギルドタイムゾーン設定（guild_timezones）

## 概要

**テーブル物理名**: `guild_timezones`
**テーブルタイプ**: Reference
**テーブルスコープ**: Guild

## 用途

ギルド（Discordサーバー）ごとのタイムゾーン設定を管理します。ユーザー入力の日時解釈および表示時の日時変換に使用されます。

## カラム定義

| カラム名 | 型 | 制約 | 説明 |
|---------|-----|------|------|
| guild_id | BigInteger | PK, NOT NULL | ギルドID（Discord Guild ID） |
| timezone | String | NOT NULL | IANAタイムゾーン名（例: Asia/Tokyo, America/New_York） |
| created_at | TimestampTz | NOT NULL | レコード作成日時（UTC） |
| updated_at | TimestampTz | NOT NULL | レコード更新日時（UTC） |

## 制約

### プライマリキー
- `guild_id`

### 外部キー
なし

### UNIQUE制約
なし

### CHECK制約
- `timezone` はIANAタイムゾーン名として有効な文字列
  - アプリケーション層で検証（chrono-tzでパース可能であること）

## インデックス

- PK: `guild_id`（自動作成）

## データサンプル

| guild_id | timezone | created_at | updated_at |
|----------|----------|------------|------------|
| 123456789 | Asia/Tokyo | 2025-01-01 00:00:00+00 | 2025-01-01 00:00:00+00 |
| 987654321 | America/New_York | 2025-01-01 00:00:00+00 | 2025-01-15 12:30:00+00 |
| 555555555 | Europe/London | 2025-01-01 00:00:00+00 | 2025-01-01 00:00:00+00 |

## デフォルト動作

- ギルドの設定が存在しない場合、アプリケーション層で`Asia/Tokyo`をデフォルト値として使用
- DBには未登録状態でも動作可能
- 専用コマンドで設定された場合のみDBにレコードが作成される

## 関連テーブル

- **なし**（他テーブルへの外部キー参照なし）

## 備考

- タイムゾーン設定変更は即座に反映される
- 既存のDB保存データ（UTC）には影響せず、表示のみが変わる
- ギルド管理者のみが設定変更可能
- サマータイム（DST）は自動的に処理される（chrono-tzによる）

## タイムゾーン設定の影響範囲

### 影響する処理
1. **ユーザー入力の解釈**
   - `/マルチバトル募集` コマンドの日時入力
   - `/マルチバトル募集内容変更` コマンドの日時入力
   - スプレッドシート読み込み時の日時解釈

2. **表示処理**
   - 募集メッセージの開催日時表示
   - 通知メッセージの日時表示
   - スケジュール表示

### 影響しない処理
- DB保存データ（常にUTC）
- 内部計算処理（常にUTC）
